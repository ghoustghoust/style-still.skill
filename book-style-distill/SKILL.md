# 文风蒸馏与写作

## 执行纪律（必须先读，禁止"已读后凭印象执行"）

- 模式 A 执行前：完整读 `references/analysis-dimensions.md`
- 模式 B 执行前：完整读 `references/writing-workflow.md` + 目标《文风档案》全文
- 模式 C 执行前：完整读 `references/knowledge-distill.md`
- 禁止仅凭本文件直接产出档案或文章

## 模式 A：蒸馏（书/文本 → 《书名-文风档案.md》）

**前置条件**：拿到文本（文件，或 ≥3 段独立节选）。

- fallback 无文本：向用户索取。触发条件：用户只给书名且坚持不提供 → 用 WebSearch 找公开书摘，档案标注「二手样本，置信度低」；**禁止凭训练记忆虚构原文例句**

1. 采样统计（仅文件输入）：`python scripts/extract_excerpt.py <文件> --samples 12` → 产出 `style-distill-<书名>/`（stats.md + samples.md）
2. 开场扫描（仅文件输入）：`python scripts/scan_openings.py <文件>` → 小节开场分布。**开场结论以全量扫描为准，不用抽样印象**
3. 逐维蒸馏：按 dimensions 的 16 维执行。前 8 维（切入/结构库/干货配比/力量点/禁区/姿态/取材/风味）定「有没有那个味道」，后 8 维定细部。每条结论附 1-3 句原文例句；无证据标注「样本中不明显」；禁令必须来自缺席证据，不照搬通用 AI 味清单
4. 合成：套 `assets/style-profile-template.md`，输出到书同目录
5. 验证（不可跳过）：仿写 300-500 字主题外文字 → 对照档案「仿写检查清单」→ 与采样并排对比 → 最多迭代 2 轮 → 结论写入档案「迭代日志」

## 模式 B：写作/润色（档案 → 文章）

**前置条件**：目标档案存在（`Grep` 搜 `*-文风档案.md`）。

- fallback 无档案：问用户指定档案或转模式 A。触发条件：用户描述的任务有明确风格对象但搜不到档案
- fallback 素材缺口：档案标注「第一手经历不可编造」且任务需第一人称 → 向用户索取真实经历，或改用第三人称/公开案例。**禁止虚构「比如有一次……」**

按 `writing-workflow.md` 的 Step 0-8 执行，硬约束：

1. **分步确认**：选材 → 结构（按命题从档案结构库推荐 2-3 种）→ 切入（给 2-3 个候选，选定后先交 100-200 字开头过目）→ 大纲（标注干货落点）→ 正文。禁止闷头写全文
2. **防重复**：写作前查档案「结构指纹登记表」——连续两篇不得共享 ≥2 维；造名等招牌动作按档案频率配给执行
3. **交付** = 正文 + 四层质检报告（L1 禁区用 Grep 机械扫描；L4 活人感终审）+ 指纹登记

## 模式 C：知识库蒸馏（任意文件夹 → 《知识档案.md》）

**前置条件**：拿到一个资料文件夹（md/txt/docx/pptx/pdf/xlsx/epub，纯图片件标记待 OCR）。

按 `references/knowledge-distill.md` 执行，硬约束：

1. **分步确认**：盘点确认范围 → 取舍清单确认（哪些要哪些不要，用户定）→ 草案过目 → 冲突人审 → 总结与清洗（删未入选数据与作废提示词）→ 验证交付。禁止闷头蒸完
2. **不编造**：每条事实带来源（文件名+页码）；拿不准进「冲突清单」交人审，不擅自定论
3. **按消费端分类**：事实/素材/红线/流程/资产，不按来源文件分类
4. **容量纪律**：主档案 ≤500 行（约 1 万 token），超出转指针；过程记录进 `_archive/`
5. **红线可机械扫描**：禁用词写成 Grep 格式，不写散文描述
6. **幻觉态度**：叙事层放开（创意源），事实层校验；能力较弱的模型改为全程压制
7. **验证**：抽 5-10 条事实回溯原文核对，错一条整批重查

产出：《知识档案.md》（写作时与文风档案并列挂载——档案管「写什么」，文风管「怎么说」）+ `_archive/` 回溯层。

**触发词**：蒸知识库、整理资料库、把这个文件夹变成知识档案、企业知识库。

## 红线

- 不虚构原文例句；二手样本必标注
- 不做无证据结论，宁可标注「不明显」
- 档案是写作工具：不输出书评、不做内容摘要
