# 模式 C：知识库蒸馏（任意文件夹 → 《知识档案.md》）

把一个任意格式的资料文件夹，蒸馏成一份 AI 写作时可全文挂载的《知识档案》。
**档案管「写什么、什么不能写」，文风档案管「怎么说」——写作时两份并列挂载。**

## 执行纪律（不可跳过）

1. **不编造**：档案里每条事实必须能回溯到原料文件；拿不准的一律进「冲突清单」交人审，AI 不擅自定论
2. **按消费端分类，不按来源文件分类**：事实（参数/数据）／素材（案例/故事）／红线（禁令）／流程（工作流）／资产（图片视频）——同一个文件里的内容可能分属多类
3. **容量纪律**：主档案 ≤500 行（约 1 万 token），一次能读完；超出的一律转「指针」（一句话结论 + 原料路径）
4. **过程与产物分离**：批次判定、去重记录、冲突历史进 `_archive/`，不进主档案
5. **红线可机械扫描**：禁用词/句式必须写成可 Grep 的形式（`词1|词2|句式`），不写散文描述

## 流程

### Step 1 盘点（先看清楚有什么）

- 递归扫描文件夹，按扩展名分类统计（数量+体积）
- 按内容类型粗分：**文本类**（md/txt/docx/pptx/pdf/xlsx/epub）／**资产类**（jpg/png/mp4/psd/ai——不蒸馏，只登记）
- 输出：盘点表 + 蒸馏候选清单（文本类文件）

### Step 2 Ingest 抽取（脚本或手工）

`python scripts/knowledge_ingest.py <文件夹> -o <输出目录>`（支持 md/txt/docx/pptx/xlsx；pdf 需 PyMuPDF；epub 建议先用模式 A 的 extract_excerpt.py）

- 每个原料产出一个带页码/幻灯片标记的 .txt，存入 `_extract/`
- **0 文本文件**（纯图片 PDF、扫描件）：标记「待 OCR」，不丢弃
- 手工替代：逐个打开复制文本亦可，脚本只是加速器

### Step 3 去重

- 同名/同内容多版本：只留**最新主版本**，旧版记录差异点
- 去重判断写入 `_archive/蒸馏过程日志.md`

### Step 4 分级与分类

- **来源强度五级**：典籍记载 / 官方发布 / 媒体报道 / 网传 / 内部材料
- 每条候选事实/素材打上：类别 + 强度 + 来源（文件名+页码）

### Step 5 合成《知识档案》（单文件，固定七节）

```
# 《名称》-知识档案
> 版本 | 蒸馏日期 | 状态（草案·待人审 / 可用）

§0 头部：原料清单（manifest 表）、冲突清单（待裁决项，逐条列证据）
§1 核心：定位、主体关系、关键口号（≤10 行，越短越硬）
§2 事实库：参数/数据表（每条标来源；低频明细转指针 → _archive）
§3 素材库：案例/故事/观察（按强度分组；招商/内部宣称单独成组并标禁用）
§4 红线禁区：禁用词（Grep 格式）、禁用句式、禁用姿态、量化承诺管控
§5 表述强度规则：强度 → 措辞映射表（典籍→直接引用；网传→"有人说"；内部宣称→禁用）
§6 消费指引：引用配额（如"每篇成分≤3"）、「深一度」信息量规则、档案间优先级
§7 变更日志：日期/版本/变更/依据
```

### Step 6 冲突人审

- 把冲突清单逐条交给用户裁决（附双方证据），裁决结论写回档案对应节 + 变更日志
- 未裁决的条目，按**更严格的一方**先行执行并标注

### Step 7 验证（不可跳过）

- 随机抽 5-10 条档案事实，回溯 `_extract/` 原文核对——错一条，整批重查
- 产出：《知识档案.md》（工作目录）+ `_archive/`（过程层）+ 验证结论写入变更日志

## 增量模式

- 新文件丢进原料仓 → 只对增量跑 Step 2-6 → 合并进主档案 → 更新 §7
- manifest 记录已处理文件（路径+日期），重复文件跳过

## 红线

- 档案产物（知识档案/冲突清单/原料内容）**永远留在用户目录，不进入 skill 本身**——skill 只沉淀流程
- 二手/OCR 来源必须标注置信度（OCR 误识别常见，引用数字前核对原件）
- 不输出内容摘要——档案是写作工具，不是读书笔记
